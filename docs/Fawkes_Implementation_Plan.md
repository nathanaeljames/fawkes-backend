# Fawkes Implementation Plan
Iteration 2 (the LLM + statechart rebuild), structured as phases. Each phase has a goal, contents, and an exit test. Phases are intentionally re-orderable at their edges; the plan is a living document — revise it, don't obey it. Not every wishlist item ships in its nominal phase; the rule is that no phase forecloses a later item (schema first, analytics later). Updated 2026-10-06, v11 (audio research groundwork: Phase 0 columns, Phase 2 collection and identification slice, ASR interface and front-end seam, the audio research program and its gating rule; gate maturity by effective duration; multi-centroid research item; thread-accumulator lifecycle; displacement limit withdrawn; maturity-aware gate, authenticated sessions as ground truth, drift monitor, per-session contribution watermark; convergence review applied: silo lock rule, immutability definition, session-end enrichment, fallback wording, scope wording for content records only; later: thread fork on pass-blurb, cluster representation and thread-end imprint enrichment, three configurable windows, threshold-based voice revocation, tunables-in-configuration rule; reconciliation of 2026-09-27 applied: scope keys in Phase 4 tunnels, warm-cache wording, Phase 0 scope tests, delivery and budget guards; owner answers on Layer 1 loading, follow-up inheritance, and root). Cross-references use base file names; versions live in git.

**Model/runtime baseline (current):** Qwen3.8-27B (Int4/AWQ-class) on vLLM (>= 0.19-class), OpenAI-compatible endpoint, thinking budget configured per pipeline (off/low for voice, high for research). Qwen3-4B-Instruct-class router/arbiter via llama.cpp; bge-m3-class embedding model on CPU until the second GPU; optional reranker. All tools are bound to pipeline slots, not to models. The voice slot is Qwen through Phase 3 and Gemma 4 from Phase 4; the research slot is Qwen.

**Hardware sequencing (one RTX 3090 until card two):** Phase 1 is text-mode with the speech stack down: vLLM at ~0.80 memory utilization holds the 27B Int4 (~16-17 GB) plus KV cache at 16K context (~2 GB; the hybrid architecture keeps KV small), the 4B router runs beside it under llama.cpp (~2.7 GB), and the embedder runs on CPU — roughly 22 GB in use. If this thrashes, develop in split mode: router/FSM eval slices against the 4B alone, recall/open-conversation slices against the 27B alone, alternating loads. Phase 2 needs the speech stack and the 27B together, which one card cannot hold: FSM voice flows run on the 4B alone (iteration-1 parity) and the 27B is swapped in for open conversation when no speech session needs the stack. Full concurrency lands with card two, where the default layout pins one model per card; tensor parallelism is an experiment gated on verified NVLink, x16 slots, and PSU headroom, adopted only on measured gain.

## Phase 0 — Milestone Zero (one afternoon)
Goal: first running code of Iteration 2; break the no-code streak; make the schema silo-compatible before any data exists, at Tier A cost only.
- Add `postgres` (with pgvector) service to docker-compose.
- Migration 001: `workspaces` and `silos` (seed one default each), `projects` keyed `(scope_kind, scope_id, project_id)`, `user_silos`, `devices` (pairing secret reference, workspace, conversation groups), `transcripts` (with runtime `event_id` as the idempotency key, `conversation_thread_id`, owner and identified-user columns), `facts` (bi-temporal), `documents`, `document_nodes`, `model_calls`, `traces`, `derived_jobs`, `pending_deliveries`, `tunnels` and `blocked_pairs` (single shared scope columns) — all content and derived tables with non-null scope kind and scope id (identity, device, role, session, and configuration records keep their separate authority), `silo_id` required for silo-scoped rows, composite foreign keys to projects, scope in every unique constraint and index prefix, content hash unique per scope, `timestamptz` UTC everywhere, enum seed tables. The facet enum is seeded here because facts can be written from Phase 0; search vectors are stored generated columns committed with the source row; `task_id` on turns is nullable. Audio research columns land here because adding them later is the expensive path: `environments` table; `environment_id` and `quality_profile` on devices; `environment_id`, `capture_quality` (JSON), `speaker_embedding` (vector), and nullable `audio_ref` on turns — all unused until Phase 2. No partitioning and no silo-keyed row-level security yet (Tier B, deferred to the first real second silo).
- `MemoryStore` skeleton taking an immutable scope context on every method: `remember_utterance()` delegating to a minimal typed `ingest()` (source row plus derived job in one transaction, acknowledged after commit), `recall()` (hybrid lexical+vector with Postgres full-text ranking, Reciprocal Rank Fusion). Phase 0 callers are a seeded test user with default workspace and silo membership.
- Tests: insert three utterances, retrieve by meaning and by keyword, assert timestamps and provenance; two identical "yes" utterances stored as two turns, a retried delivery of one stored once; kill the process between commit and embedding, restart, assert the row exists and the derived job completes without a duplicate; ingest in silo A and query as silo B through facts, full-text, and vector paths, assert empty; attempt a cross-silo tunnel insert, assert the constraint fails. Fixtures cover workspace, user, and silo scopes: a same-scope tunnel succeeds and a cross-scope tunnel fails; a document is deduplicated within a scope and stored separately per scope; an invalid project/scope pair is rejected.
Exit: `pytest` green; a transcript survives a container restart; the silo leakage tests are permanent markers.

## Phase 1 — Cognitive core + substrate foundation
Goal: the new brain exists; the old Rasa functionality is reachable through it in text, while iteration 1 keeps running in parallel.
- Prompt builder (Layers 0-1 and the Layer 2 topic slice in text mode, each defined by what it carries and how it is fetched per Architecture Specification C-07; frozen-snapshot injection of the topic slice; local-time and elapsed-time rendering per session; scope assertion on every context item) + validator skeleton with bounded re-prompt of the proposer (two additional attempts), all-or-nothing ratification of a structured output, and post-ratification confirmation text (FSM template or second short generation); structured-output JSON contract with a confidence field; FSM registry data structures with workflow state keyed by user, scope, and instance.
- Small-model router v1 for the voice channel: {FSM event | ignore/backchannel | escalate} with confidence; wired before the voice-slot model; Layer 2 retrieval runs only on escalate verdicts. Two harness-gated experiments ride on the same call: retrieval hints (entities, topic, active-project guess) emitted in the verdict and consumed by the Layer 2 topic slice at no extra round-trip, adopted only if the recall slice improves; and a complexity flag for the voice-path latency gate, adopted only if the routing slice holds.
- vLLM serving for the 27B; llama.cpp serving the 4B on the same card; prompt prefix ordered for cache stability. Serving-recipe experiment: stock vLLM vs the tuned vLLM fork (draft-model speculative decoding, requantized embeddings) vs the tuned llama.cpp fork (long context), scored by the eval harness for decode speed at short and deep context, tool-call validity, and stability; the winner recorded in the toolbox with data. Prefix caching over the hybrid-attention layers is measured first, because the verbatim Layer 2 project slice (Phase 2) depends on it holding.
- Ontology v1 (`ontology.md` + enum tables + constraints; facet vocabulary v1: fact / preference / decision / event / task-state), planned before the facts table takes data, evolved only via versioned migrations.
- `ingest()` v1 with content hashing, provenance, silo/project stamps, and fan-out handler registry; turns, traces, and model-call cost rows all enter through it.
- Eval harness v0: ~30 seed cases sliced by task family with deterministic scoring (labeled routing verdicts, seeded recall facts with expected citations, fixed-corpus multi-hop citation ids, schema validation, loop/stop/latency observation); the coding-patch slice arrives in Phase 3 with the coding surface; nightly smoke subset plus full runs on fingerprint change and weekly; first capability cards written to `capability_cards`; `feedback_events` table created (schema first) so corrections, re-asks, and thumbs can be captured as soon as a channel produces them.
- CI pipeline (GitHub Actions): unit tests for the deterministic core (test-first), integration tests against Postgres, mocked-LLM FSM lifecycle walkthroughs via a shared `FakeLLM` fixture, silo leakage tests, secret scanning on every push; Phase 0 and Phase 1 exit tests as permanent pytest markers.
- Observability schema: one JSON trace per turn/call including stage timings, retrieval results, FSM state, model, tokens in/out/cached, task id, silo, and (for external calls) cost; backup cron for Postgres.
- Postgres operations: shared_buffers sized to hold the vector and full-text indexes; pg_prewarm at startup so voice-path retrieval normally runs from warm pages (a measured target, not a guarantee; cold-start and memory-pressure latency recorded); Budget A (pre-LLM assembly, tentative ~150 ms) measured in text mode with the embedder on CPU, and the embedder moved to GPU or swapped for a smaller model if it does not fit.
Exit: text-mode conversation through the statechart passes the eval set's FSM and recall slices; every turn produces a trace record; a first capability card exists for each served model; CI green.

## Phase 2 — Voice memory + identity (voice is primary)
Goal: full voice loop on the new core, multi-user, with real memory; Rasa retired.
- Layers 0-2 tiered loading on the voice path, including the Layer 2 project slice: Layer 1 loads in two steps (1a after one positive identification, 1b together once the thread's cumulative voiceprint reaches high-certainty identification, three consecutive identifications as fallback); the semantic cache is keyed by permission set; Layer-3 single-shot lookups include weather and web lookup (one search-API query returning snippets) but never web research, which stays research-only. Project slice detail: verbatim recent turns of the active project under a token cap (2-4K placeholder, set by the harness's recall slice), loaded by SQL when the active project resolves, refreshed at session boundaries, placed in the cache-stable prefix; older sessions as idle-window summaries plus pointers; the topic slice injected as a frozen snapshot per escalated turn. Semantic cache keyed by permission set (principal, area, scope, assurance). Layer-3 tool calls (remember/recall/single-shot lookups such as weather and web search), fast-class tools only on the voice path, at most one tool round per turn under Budget B (tentative ~500 ms). Tool registry carries a latency class per tool.
- Enrollment FSM ported as a workspace-scoped workflow that creates an identity (provisional record, voiceprint, consent — verify the consent step at the port; no user-area access; the optional passphrase step is dropped in favor of the pass-blurb); voice-clone FSM ported; auth FSM (deferred identification tiers, recency-modulated thresholds, pass-blurb: a rotating pre-recorded passage pushed to the user's registered device and read aloud) raising a device to user level; delivery channel for pass-blurbs in Phase 2 is the simplest available (paired screen, SMS, or a minimal push channel), the companion app if it exists; Rasa switched off once lifecycle tests and eval slices pass.
- Identity outside silos: user_silos membership with a default silo per user; project resolution from voice (active project in Layer 1 or explicit command) — settled before the enrollment port.
- Workspace and user access levels: device pairing with an issued device secret (static configuration tokens in Phase 2; voice-approved administrator pairing in Phase 5); per-workspace authorization of devices, apps, actions, and FSM functions; continuous per-utterance speaker identification driving per-utterance authorization, with identification evidence pooled per conversation thread across the conversation group; Layers 1a and 1b together on cumulative high-certainty identification (three consecutive as fallback); pass-blurb required for user-area reads and for personal-project questions before Layer 1b, not for writes to the speaker's own store; pass-blurb challenge protocol (issuance, expiry, binding, single use, replay rejection, rate limits); one utterance is one evidence unit; revocation invalidates cached Layer 1b content; facts promoted from identification-only threads held unconfirmed; Layers 1a and 1b load together once the thread's cumulative voiceprint reaches high-certainty identification (three-consecutive rule as fallback; the split retained as a configurable distinction); within the follow-up window a group microphone that verifies the speaker inherits user-level authorization without having observed the pass-blurb; listen-along binding is audio-domain (energy-envelope and voice-activity alignment), with transcript matching only during handoff overlap; voice-derived authorization is revoked by thresholds (three consecutive non-owner utterances on a device for the user area; two consecutive during a silo session lock the entire silo session, voice and text, pending the PIN while the user-area sign-in survives; never for text-, web-, or app-initiated sessions), each utterance still served only at its own speaker's assurance; a pass-blurb inside a workspace thread forks it into a user-scoped continuation; three windows — follow-up, thread-continuation horizon, session timeouts — are separately configurable, and a rejoined thread continues its accumulators; tests: a single foreign utterance does not revoke; the third consecutive does; a fork leaves no private reply in the workspace store; conversation groups; conversation threads across devices; promotion of a workspace conversation to the user area on continuous identification; visibility markers on standing-context facets; area-weighted retrieval (user → workspace); audit rows for every authentication event and scope transition.
- Operational data migration: iteration-1 DuckDB tables into Postgres; ECAPA matrix built from Postgres at startup; DuckDB retired.
- Voice register: thinking off/budgeted, brevity persona, stall words; correction-event hook (queue + prompt-builder input) that also carries research results and self-corrections back to the voice channel.
- Memory-promotion hook (small model) after each turn.
- Wake and session manager: on-device wake-word detection on every device; beacon election; session and follow-up windows; listen-along streams from mains-powered group microphones; hysteresis re-election from stream quality; overlap binding; the continuity judge; binding events; the microphone-handling matrix (Specification D-12) as acceptance cases.
- Speaker matcher extended with a per-thread, per-speaker-cluster accumulator and a prior-aware decision rule (verification against a hypothesized speaker with the full matrix scored in parallel); Phase 2 tests: five short utterances accumulate to one identification; two people near one microphone become two speaker tracks inside one thread with separate scores; two genuinely independent conversations sharing a microphone stay separate threads; a speaker entering a room where another is talking binds to their own track and never merges into the other's. Stored-imprint enrichment runs at session end (follow-up window expiry) behind a certainty gate, as one duration-weighted update of that session's own summary, no cap and no displacement limit, behind a maturity-aware gate (loose for young imprints, tightening with accumulated effective duration); pass-blurb sessions contribute as ground truth subject to cluster purity; a drift monitor offers re-enrollment on declining confidence; a contributed watermark per session prevents resubmission of reloaded thread accumulators; tests: a weak enrollment imprint converges under clean sessions; an authenticated low-cosine session still contributes; one hundred sessions in a thread contribute exactly one hundred times; gate maturity is a configured curve over effective duration, never age or count. Research item (Phase 2): multi-centroid imprints — collect per-device identification scores for each user, and if one environment (car, phone) shows a distinctly higher false-rejection rate under the single-mean imprint, prototype per-user centroids keyed by device and merged or split by environment. Audio research collection (Phase 2, when the audio pipeline is ported): compute tier-1 capture statistics (speech-to-noise ratio, clipping, bandwidth, reverberation estimate) for every utterance on the dominant stream and store them with the utterance's ECAPA embedding on the turn; maintain the device quality profile; record per-stream quality and estimated time offset on every overlap binding event (raw material for multi-microphone separation and localization later); port ASR behind the C-03 streaming interface and the C-02 per-consumer front-end seam; add a speaker-identification evaluation slice (per-device and per-environment false-rejection and false-acceptance from pass-blurb-labeled sessions) to the harness — this slice is what decides whether audio work is pulled forward. Multi-centroid acceptance test: the failing environment's rate falls to the home rate without raising the home false-accept rate. Thread accumulators live in memory per session, persist with the thread, reload on rejoin, and are deleted when the thread closes; each applied workflow state is kept as an immutable versioned snapshot while the live instance advances (cluster resolved at high certainty, accumulated signature verified against the stored imprint, minimum quality-weighted duration, no speaker conflict), capped per thread and versioned for rollback; per-utterance identification is read-only in memory. Tests: an imprint is enriched once per thread, not per utterance; a polluted cluster does not enrich; a rollback restores the prior imprint and matrix row.
- Satellite hardware: evaluate Satellite1 or ReSpeaker Lite (ESP32-S3 + XMOS front end) as the wall unit; Fawkes WebSocket framing with the Wyoming message vocabulary; echo cancellation verified so the unit does not hear Fawkes's own speech as overlap.
- Sandboxed tool container.
- Interim single-GPU fallback: FSM voice flows on the 4B alone whenever the 27B cannot be co-resident.
Exit: two different speakers hold personalized conversations on separate devices; enrollment completes end-to-end; a second speaker on an authenticated device cannot read the first speaker's user-area memory (per-utterance authorization test); a workspace conversation is promoted to the user area with original timestamps; a fact stored yesterday is recalled with citation and correct local date today; voice-path pre-LLM overhead (Budget A) measured against the tentative ~150 ms target and a one-tool-round turn (Budget B) measured against the tentative ~500 ms target, both budgets revised from the measurements; time to first audio recorded for no-tool and one-tool turns; lifecycle walkthroughs for all ported FSMs green in CI.

## Phase 3 — Ingestion, research pipeline, external hands, dual-pipeline interplay
Goal: Fawkes reads, researches, codes, talks to the outside world, and the voice pipeline rides alongside the research pipeline.
- Ingestion source adapters: file drops and coding-session transcripts → `ingest()` (browser and terminal adapters deferred to Phase 6+); ingestion router (structure scoring; Qwen-vision OCR at ingest); document-summary selection layer; PageIndex-style trees in `document_nodes` (checksum-cached).
- Research pipeline v1: agentic loop with grep/FTS/tree/web tools, CRAG grading, web fallback; LLM-guided document-tree descent lives here only (node lookup is a fast tool available to voice Layer 3); recall ladder with context expansion and citations; job checkpoints to MemoryStore; text responses returned to text clients; correction events raised for voice-initiated tasks; ~4 medium-depth workers as the fan-out design point.
- Code tools: ripgrep + fuzzy + tree-sitter tiers; adopt code-graph MCP servers as shipped (code-review-graph for blast radius and impact; graphify for the multimodal bird's-eye view), per-commit incremental updates, consumed by OpenCode and the research pipeline.
- Router extended to the text channel as arbiter: {start (dispatch now) | queue for next boundary | interrupt | FSM command}, never discard; ~5 s default-to-queue timeout; illegal FSM commands return to the arbiter.
- Rubber-duck interplay v1 on the single served Qwen: blackboard (notes-up), imperative channel direct to the research command queue (start/queue/interrupt), read-down status board + deep transcript access, arbiter machinery with out-of-band cancel naming task and generation ids, one disposition per message, no automatic re-run of side-effecting tools; research model resteers itself.
- Durable pending deliveries: completion and delivery recorded separately; results delivered exactly once to any of the user's text devices at the required assurance level; voice access to user-scoped results after user authentication. Delivery protocol: delivery ids, claims, acknowledgements, deduplication on re-offer, assurance re-validated at delivery; text-initiated results appended to the originating thread; voice-initiated results spoken on the thread's last device within a 60-second activity window, else recorded in the thread, or pushed to an identified user's preferred device (notification opens a voice channel); budget reservation per remote call in the external bridge. Outcome-unknown remote calls (timeout after dispatch) stay counted against the cap until reconciled; a concurrent worker cannot reuse that allowance; a confirmed non-billable failure releases immediately. Delivery guards: a recent thread is a destination, not a permission — private results play only where the required assurance is still held, silo results only on the active silo device.
- Consolidation/compaction jobs + scheduler (idle-window arbitration).
- OpenCode integrated as coding surface; its transcripts ingested.
- Coding-patch eval slice: 10-15 hand-authored micro-repositories (5-30 files each, a task statement, failing tests) drawn from our own past bugs, stored under `tests/eval/repos/`, optionally supplemented by a small public subset (HumanEval+ or Aider polyglot); the harness copies each to a temp directory, runs the coding loop, applies the patch, runs the suite; weekly cadence, and included in full card runs.
- MCP server over MemoryStore (scoped auth by silo, user, project; audit log) — consumed by OpenCode; usable by Claude.
- External API bridge: Claude escalation tool under the adopted policy (disabled until a scoped policy is enabled; complexity as primary trigger; explicit request overrides the complexity gate but not the budget; per-request stateless context bundles with prompt caching; Claude as subagent, never session host; every remote turn stored locally), remote tier selection from capability cards, OCR-first text/JSON/Markdown payloads, budget gate with monthly and per-task caps, per-call cost accounting, silo-stamped audit log; remote tiers scored once per model release and spot-checked monthly on a capped sample.
- Salience weights v1; contradiction detector v1 (log-level); per-task token/cost rollups and expensive-task flags.
- (~Phase 3.5, as VRAM pressure dictates) SSM/Mamba ASR swap for interim and final slots — a substitution behind the C-03 interface, validated on the recall and latency slices; the streaming slot is where the state-space payoff is largest (fixed hidden state, linear cost), and the swap is the point at which N-best output and the speaker-conditioning hook are first exercised.
Exit: a multi-document research question answered with correct citations; a coding task completed in OpenCode with Fawkes memory available via MCP and code-graph context; one Claude escalation round-trip carrying extracted text rather than a document; a voice question about the live research session answered from the status board; a mid-flight correction delivered through the arbiter; a text-channel message started, queued, and interrupting in three separate tests; a voice-initiated research result delivered by voice.

## Audio research program (cross-phase)
The owner expects to return to audio repeatedly. To keep it from displacing the core goals, audio work follows one rule: it is pulled forward only when the speaker-identification slice shows a measured problem on a device in daily use, or when a phase's exit test depends on it. Groundwork that is cheap now and expensive later is laid regardless: the Phase 0 schema columns; the Phase 2 collection, seams, and evaluation slice. Everything else — enhancement models (denoise, dereverberation; A/B'd per consumer, since they can hurt speaker embeddings), per-environment profiles beyond the stored columns, multi-centroid imprints, multi-microphone separation assist, the SSM ASR swap, and the Cocktail Party track — is research scheduled by evidence, not by calendar.

## Testing and evaluation cadence (all phases)

| Cadence | Where | What runs | Purpose |
|---|---|---|---|
| Per commit | GitHub Actions, no GPU, seconds | Unit tests for the deterministic core; integration tests against Postgres; FSM lifecycle walkthroughs against the shared `FakeLLM` fixture; schema contract tests proving ontology constraints hold; silo leakage tests; arbiter protocol tests (start/queue/interrupt/timeout); secret scanning | Regression armor; a phase exit test never leaves this suite |
| Nightly | Workstation, GPU, minutes | Smoke eval: a fixed ~10-case subset (routing verdicts, seeded recall, structured-output validity) against the currently served local models, plus latency timings; results appended to the eval log, no new card unless the fingerprint changed | Catch drift from prompt, harness, or config edits within a day |
| On fingerprint change (as needed) | Workstation, GPU, tens of minutes | Full local capability-card run: every applicable slice, several sampling seeds → new card version; the evaluation case set is versioned so a score names both the fingerprint and the case-set version | Re-measure whenever model, quant, serving config, prompt version, or index contents change |
| Weekly | Workstation, GPU | Full card run even without a fingerprint change (never skipped by the unchanged-fingerprint rule); the coding-patch suite (once it exists, Phase 3) runs here, not nightly | Catch environmental drift (drivers, libraries, index growth) |
| Per remote model release, plus a monthly capped spot-check | Anthropic API, budgeted | Remote-tier cards on the research-tier slices only (multi-hop, complex reasoning, coding patch if remote coding escalation is enabled) — never routing or voice-recall slices, which no remote model ever serves | Keep tier selection honest at bounded cost |
| Opportunistic | Whenever panel mode runs | Per-model tokens, loops, compute time, and judge rubric grades on the same real task, written to `panel_results` and summarized onto cards as field observations, labeled as uncontrolled | Head-to-head evidence on real tasks that the seed set cannot produce |

- The general eval harness (all local slices, all cadences above) and the card-stamping routine (the subset that produces a versioned card row) are the same code; a card is simply the harness output frozen at a fingerprint.
- Feedback capture is schema-first: a `feedback_events` table exists from Phase 1 (turn_id, task_id, kind: thumbs_up / thumbs_down / explicit_correction / re_ask / confirm / abandon, source channel, payload, silo). Phase 2 fills it from voice via the router (a correction class: "no, I meant…", re-asks of the same intent within a window, verbal thumbs) and the promotion hook; Phase 5 adds thumbs up/down in the web interface. Every feedback event links a turn to a task, so exchanges-before-answer is derivable later from transcripts alone.
- Every phase exit test is a permanent pytest marker; later phases may not break earlier exits.
- Test-first for the deterministic core (validator, FSM registry, ingest idempotency, MemoryStore contracts, arbiter machinery); prompts iterate against the eval harness instead.
- Voice-path budgets A (~150 ms pre-LLM assembly) and B (~500 ms single tool round), the tool latency classes, and the Layer 2 project-slice cap are tentative until measured at Milestone Zero and Phase 2; the measured values replace them here and in the specification.

## Standing constraints (all phases)
- Multi-user support never regresses; silo isolation never regresses; authorization is per utterance, never per device session.
- No reasoning-driven retrieval on the voice hot path.
- ASR text never reaches the research pipeline except through the voice pipeline; text-channel messages are never discarded; voice in means voice out, text in means text out.
- Any memory transformation writes a manifest; any retrieval writes a trace; any model call records tokens and cost.
- Every adopted component sits behind a seam (OpenAI-compatible endpoint, MemoryStore interface, MCP); tools are bound to slots, not models.
- Outbound cloud payloads are extracted text and structured data unless visual judgment is the task.
- Project documents contain nothing that cannot be published.
- Tunables (windows, thresholds, budgets, retry bounds) live in the configuration area, never as literals in code.
- Document set (wishlist, principles, inventory, plan, toolbox, handoff, architecture specification, diagram sources) updated in full whenever a decision changes it, with an explanation of what changed and why. Documents are cumulative: a regenerated document is diffed against its previous version, every removal or shortening is itemized as a deliberate supersession with its reason, and nothing else is compressed or dropped.
