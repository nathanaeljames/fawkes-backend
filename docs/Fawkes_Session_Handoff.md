## Standing rules (recorded in assistant memory as well)

- Never proceed if a referenced file/URL/document is missing — stop and ask.
- Expand uncommon acronyms on first use.
- Multi-user support at every stage; never regresses. Silo isolation never regresses. Authorization is per utterance, never per device session.
- Any input meriting a change to project files returns the full revised file(s) in the same turn, with an explanation of exactly what was edited and why; only files that actually change are regenerated.
- **Project documents are cumulative.** Recorded content leaves a document only when the owner expressly removes it, a later decision supersedes it, or it is shown to be wrong. An assistant never deletes, shortens, or "tidies" recorded content on its own initiative; condensing for length is a regression.
- **Regeneration protocol.** Before a regenerated document is returned, it is diffed against the previous version (the repository copy or the last delivered version). Every removed or shortened passage is itemized in the same turn as a deliberate supersession with its reason; a regeneration with no removal list may remove nothing. Restatements and additions are free; removals are never silent.
- New versions are delivered in chat under a new version suffix (v2, v3, v1.4), never under the previous file name; the repository stores the base file name and git holds the history; internal cross-references use base names.
- The Claude Project's uploaded copies are refreshed from the repository after every commit; the repository is the reference version for any diff.
- Project documents are publishable as written: no secrets, hostnames, employer names, or third-party personal names.
- Patch-style code edits with surrounding-context anchors; no unsolicited refactors; no emoji; Mermaid house colorway with the semantics and complexity levels recorded in the toolbox.
