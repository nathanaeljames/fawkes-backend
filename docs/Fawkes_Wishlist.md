# Fawkes Wishlist v4
Updated 2026-09-25 (later). Supersedes Wishlist v3 (the 2026-09-19 text restored in full; the 2026-09-20, 2026-09-21, 2026-09-24 and 2026-09-25 decisions applied; the three-tier access model and the twelve review answers added). Supersedes the original wishlist. Every feature mentioned across all conversations to date, prioritized by emphasis and mapped to the implementation phase where it lands. Phases refer to Fawkes_Implementation_Plan.md. Not every item ships in its nominal phase; the standing rule is that infrastructure never forecloses an item (schema first, analytics later).

## Tier 1 — Core commitments (Phases 0-2, high priority)

- LLM + hierarchical state machine (statechart) dialogue core replacing Rasa; the LLM proposes, a Python validator ratifies, and a rejected proposal returns to its proposer with a constraint hint a bounded number of times. Phase 1 builds the machinery in text mode; Phase 2 recreates the Rasa workflows over voice and retires Rasa. [Phase 1-2]
- Silo layer, Tier A, from migration 001: a `silos` table with one seeded default, every content and derived row stamped with a non-null `silo_id`, projects keyed `(silo_id, project_id)`, `silo_id` in every unique constraint and index prefix, tunnels and blocked pairs unable to represent a cross-silo link, content hash unique per silo, semantic cache and traces keyed by silo, an immutable silo context on every MemoryStore call, and permanent leakage tests. Identity (speakers, imprints, devices) lives outside silos with a membership table and a default silo per user. Tier B (derived tables list-partitioned by silo, silo-keyed forced row-level security under a non-owner role, per-silo roles, instance pin) waits for the first real second silo. Fawkes runs one silo; the schema is ready for many-per-database or one-per-database. Every content row carries a scope kind and scope id (workspace, user, or silo) with `silo_id` required exactly for silo-scoped rows; projects may live in any scope (the owner change formerly pending as Specification Q-09, landed 2026-09-25). [Phase 0-1; Tier B Phase 5+]
- Three-tier access model (Specification R-12, C-33, D-10): workspace level — registered devices, apps, actions, and FSM functions authorized per workspace, no authentication, Fawkes as a household Siri replacement; user level — voice authentication with a randomized challenge phrase and high-confidence voiceprint, device biometrics unlocking a device-bound key, or web sign-in; silo level — web sign-in plus a second factor, one device-exclusive session per silo, short idle timeout and absolute lifetime. Authorization is evaluated per utterance against continuous speaker identification; conversation groups define which devices may inherit an authentication (home yes, car no). Timeouts configured separately per level. Every authentication event, scope transition, pairing, and silo entry audited. Unenrolled voices matched transiently, never persisted; enrollment records consent. [Phase 2 workspace and user levels; Phase 5 web sign-in and silo sessions]
- Workspace conversations with continuous identification: unidentified turns live in the workspace store; conversation threads recognized across devices by topic and timing; on high-confidence identification the turns are tagged with the user and the workspace-visible subset of Layer 1 loads; on "make this private" the thread is voice-authenticated and moved to the user area with original timestamps and an audit row. Standing-context facets carry a visibility marker. Retrieval reads the current area plus the areas below it with descending weights (silo → user → workspace). [Phase 2]
- Durable pending deliveries: task results wait keyed to task, user, scope, and channel type and are delivered exactly once to any of the user's text devices at the required assurance level; text sessions are chats listed per user; voice access to user-scoped results requires user authentication; silo results only inside the active silo session. [Phase 3, 5]
- Input routing doctrine (three channels). Voice: all ASR text goes to the 4B router, which discards noise, advances FSM workflows (rendering tiny in-workflow replies itself), or escalates everything else to the voice-slot model; the voice-slot model may also propose FSM transitions that need conversational context or that the router missed; nothing from ASR reaches the research pipeline except through the voice pipeline. Text (web/app): all text goes to the 4B acting as arbiter, which starts a research task immediately, queues it for the next loop boundary, or interrupts a running task — never discards; text may also trigger an FSM command, and an illegal command returns to the arbiter. Rubber-duck powers: the voice-slot model may answer, write a blackboard note, or issue start/queue/interrupt imperatives straight to the research command queue. Response modality follows input modality. [Phase 1-3]
- Small-model router (Qwen3-4B-Instruct class) as FSM front line and arbiter; upgrade to a 14B-class utility model only if the 4B fails the routing eval slice. [Phase 1-2]
- MemoryStore on Postgres + pgvector + full-text search: verbatim timestamped transcripts (every turn, both roles), documents and document trees, bi-temporal facts table. [Phase 1]
- Single `ingest()` write path: content hashes, idempotency, provenance stamps, silo/project stamps, fan-out to derived stores; turns, traces, and model-call cost rows enter through it too. [Phase 1]
- Hand-written versioned ontology (entity types, relation types, facet taxonomy: fact / preference / decision / event / task-state — approved 2026-09-24 as the replacement for MemPalace's halls; a starting set extended only by versioned migrations; candidates insight and advice noted, not adopted) enforced at runtime by enum tables and constraints; evolved only through versioned migrations. [Phase 1]
- Evaluation harness from day one with deterministic scoring per slice (task family): ~30 seeded cases across voice recall, research, coding; behavioral checks (valid tool calls, no loops, facts maintained, clean stops); labeled routing verdicts, seeded recall facts with expected citations, fixed-corpus multi-hop citation ids, schema validation, loop/stop/latency observation; behavioral checks; latency timing at the API boundary; a reference-anchored LLM judge only for free-text slices; nightly smoke subset, full runs on fingerprint change and weekly; real-usage corrections become new labeled cases; per-model capability cards (versioned rows per model, quantization, and serving config with per-slice accuracy, latency percentiles, tool-call validity, loop and stop rates, cost per task) read by the router and the external bridge; paid remote tiers scored on research-tier slices only, once per release and spot-checked monthly on a capped sample; panel-mode outcomes recorded as field observations on cards. Capability cards derived from segmented results; the harness gates phase exits. Coding-patch slice (small failing-test repositories) added in Phase 3. [Phase 1]
- Feedback capture, schema first: a `feedback_events` table linking thumbs, explicit corrections ("no, I meant…"), re-asks, confirmations, and abandonment to turns and tasks; filled from voice via the router and promotion hook (Phase 2) and from the web interface (Phase 5); the raw material for exchanges-before-answer and for the eval regression set. [Phase 1 schema; Phase 2, 5 capture]
- Serving-recipe experiments measured, not assumed: stock vLLM vs tuned vLLM fork (draft-model speculative decoding, requantized embeddings) vs tuned llama.cpp fork (long context), scored by the harness. [Phase 1]
- Continuous-integration functional test suite on every commit (GitHub Actions): unit tests for the deterministic core, integration tests against Postgres, full FSM lifecycle walkthroughs driven by a shared mock-LLM fixture, silo leakage tests, secret scanning; every phase exit test codified as a permanent regression marker. [Phase 1]
- Structured observability with token and cost accounting: one JSON trace record per turn/call (stage timings, retrieval results, FSM state, model, tokens in/out/cached, external cost, task id, silo); per-task rollups flag expensive work for review. [Phase 1]
- vLLM as the serving runtime now, behind the OpenAI-compatible `/v1/chat/completions` boundary; Qwen3.8-27B (Int4/AWQ-class quant) as primary model; 4B router via llama.cpp on the same card; embedder on CPU until the second GPU. [Phase 1]
- Multi-user and multi-endpoint support at every stage (hard requirement, not a feature). [All phases]
- Tools bound to pipeline slots, not to models: the tool registry, MemoryStore access, transcript access, and web search are available to whatever model occupies the voice or research slot on a given day; every registered tool carries a latency class (fast/slow) and the voice slot sees fast tools only. [All phases]
- Tiered voice-path context loading, each layer defined by what it carries and how it is fetched: Layer 0 persona (directives, voice register, boundaries) and tool registry, static and prompt-cached; Layer 1 per-user standing context (promoted durable facts, active projects and goals, research status board) by SQL on ECAPA resolution; Layer 2 project slice (verbatim recent turns of the active project under a token cap, older sessions as summaries with pointers) by SQL when the project resolves, cache-stable; Layer 2 topic slice (utterance-relevant memories weighted to the active project) by hybrid search per escalated turn, injected as a frozen snapshot and discarded next turn so retrievals never accumulate; Layer 3 tool-called deep search (whole-silo transcript search, SQL-join fact lookups, document-node lookup, research-transcript access), fast-class tools only on the voice path. [Phase 1 (text) / Phase 2 (voice)]
- Sub-second voice-path retrieval: deterministic SQL fact lookup (SQL hops, fast through three to four joins at our scale), semantic cache, hybrid lexical+vector with Reciprocal Rank Fusion over the whole utterance (no keyword-selection step; lexical ranking is Postgres full-text ranking, BM25 via extension only if the recall slice demands it — owner answer Q05, superseding the earlier "BM25" wording); no extra LLM round-trips on the hot path; reasoning hops belong to research. Voice-path budgets, tentative pending measurement: Budget A pre-LLM assembly ~150 ms, Budget B one tool round of fast-class tools in parallel ~500 ms; beyond B, stall word, provisional answer, research task. Experiment: the 4B router's verdict carrying retrieval hints and a complexity flag in the same generation. [Phase 2]
- Deferred, risk-based voice authentication: unidentified → voice-identified → authenticated tiers; recency-modulated ECAPA thresholds; randomized challenge-phrase auth FSM; retroactive attachment of buffered turns on identification. Enrollment is a workspace-scoped workflow that creates an identity (provisional user record, voiceprint, consent, optional passphrase step) and grants no user-area access. [Phase 2]
- Enrollment and voice-clone FSMs ported to the new statechart. [Phase 2]
- Operational data migration: iteration-1 DuckDB tables (speakers with ECAPA/XTTS imprints, pangrams, passages) migrated into Postgres; DuckDB retired completely; the in-memory ECAPA matrix is built from Postgres at startup. [Phase 2]
- Timestamps (date and time) on every turn, fact, resource, and modification, stored as UTC `timestamptz`; each device/session registers an IANA time zone; the prompt builder renders local time and elapsed time per session. Time is not optional. [All phases]
- Everyday question answering and single-shot tools (reminders, fact storage/recall, weather, timers). [Phase 2]
- Stall-word / provisional-answer support in the voice register ("let me look deeper into that, but here is what I can say for now"), with a correction-event hook that delivers background-verification results, voice-initiated research results, and self-corrections back by voice. [Phase 2]
- Sandboxed (Docker) tool execution; no agent access to project root. [Phase 2]
- Per-turn memory-promotion hook: after each turn a small model judges whether anything is a durable fact/preference/decision worth promoting to standing context and the facts table. [Phase 2]
- Interim single-GPU fallback: FSM voice flows on the 4B router alone whenever the 27B cannot be co-resident with the speech stack. [Phase 2]

## Tier 2 — Research, coding, knowledge, external hands (Phases 3-4)

- Research pipeline: agentic loop (grep/FTS/tree/web tools), CRAG-style relevance grading, web-search fallback, multi-hop reasoning, parallel fan-out for breadth-first tasks (~4 concurrent workers at medium depth as the design point); job checkpoints for crash recovery; text responses to text clients. [Phase 3]
- OpenCode adopted as the coding surface, pointed at the local vLLM endpoint, transcripts flowing back into MemoryStore. (DeepSeek Harness on watchlist as alternative.) [Phase 3]
- Code tools: ripgrep + fuzzy + tree-sitter tiers; adopted code-knowledge-graph MCP servers used as shipped with their own storage — code-review-graph for callers/callees, blast radius, and PR-grade impact, graphify for the multimodal bird's-eye view (docs, PDFs, images, community detection) — updated incrementally per commit, serving OpenCode and the research pipeline. [Phase 3-4]
- MemoryStore exposed as an MCP (Model Context Protocol) server with scoped read/write auth (silo, user, project) and audit log, consumable by OpenCode, Claude, and other agent hosts. [Phase 3]
- External API bridge (Claude and other remote models): cloud use disabled until the owner enables a scoped policy (tasks, tiers, monthly budget, per-task cap); complexity is the primary trigger, an explicit request overrides the complexity gate but never the budget, local confidence is secondary; each escalation is a single stateless request with a locally assembled context bundle (prompt-cached within a task) — Claude as a subagent inside a locally hosted task, never the host of a session; remote-model tier selection from capability cards; OCR-first payloads (Fawkes extracts text/JSON/Markdown locally and forwards text, never PDFs or screenshots, unless visual judgment is required); per-call token/cost accounting with every remote turn stored locally like a local turn; silo-stamped audit log; a denied call makes no external request. [Phase 3]
- Ingestion source adapters: file drops and coding-session transcripts. [Phase 3] (Browser text-extraction sidecar and terminal capture deferred — see Tier 4.)
- Ingestion router: document structure scoring; route to PageIndex-style trees (stored in Postgres), hybrid search, or lazy-only handling; OCR via Qwen vision at ingest. Document-node lookup (SQL, milliseconds) is a fast voice tool; LLM-guided tree descent is research-only. [Phase 3]
- Document-selection layer: per-document summaries, BM25+vector searchable. [Phase 3]
- Recall ladder: standing context → hybrid search → rerank → context expansion → synthesized answer with citations, or an honest "not found." [Phase 3]
- Rubber-duck dual-pipeline interplay v1 on the single served Qwen: shared blackboard in MemoryStore and status board (notes-up, read-down, imperatives) with the blackboard carrying notes only; imperative channel (start/queue/interrupt) direct to the research command queue; read-down via a status board (research summary refreshed at every loop boundary, injected into voice Layer 1) plus deep access to the full research transcript through voice Layer 3 tools; arbiter triage into discard (voice-origin only) / start / queue / interrupt with a ~5 s default-to-queue timeout; research model performs its own resteer. [Phase 3]
- Background consolidation and compaction: summaries-with-manifests, archival with stub pointers, idle-time scheduling. [Phase 3]
- Wiki distillation layer, OKF-conformant (Open Knowledge Format bundles), one per project (therefore per silo), lifecycle states, lint cron. [Phase 4]
- Project tunnels with full lifecycle, within a silo only: autonomous proposal (attributed), explicit-command crossing, reinforcement on use, decay on veto, destruction on request. [Phase 3-4]
- Ingest-time contradiction detection; severity-gated: log, or clarification FSM. [Phase 3-4]
- Confirmation discipline: for any turn proposing an FSM transition, the model's response text is a draft and the spoken or written confirmation is produced only after the validator applies the transition (FSM template or a second short generation) — success text never precedes ratification; a structured output is ratified or rejected as a whole. [Phase 1]
- Salience/importance weights: explicit marking, recency, retrieval frequency, goal linkage; component scores stored, decay over time. [Phase 3]
- Reconciliation crons (store agreement sampling) and wiki lint (orphans, staleness, gaps). [Phase 4]
- Gemma 4 as the voice-slot model alongside Qwen (arrives with second RTX 3090, one model per card by default): conversational register plus decorrelated judgment; listening tests decide. [Phase 4]
- Panel mode (decorrelated judgment): identical-spec parallel execution by two models with an arbiter strategy (judge-selects, vote, synthesize, test-harness-wins), and decision-point consensus where only extracted key decisions are cross-checked; reserved for complex, critical, or sensitive tasks; available inside heads-down mode. [Phase 4]
- Heads-down mode: a task-mode switch that swaps the conversational model's GPU slot for a second coding model (GLM-class, size permitting) or a retrieval model (Harness-1), with the voice pipeline falling back to a Qwen-driven register. [Phase 4+]
- Autonomous research tasks (deep-research style) with sub-task decomposition, parallel execution, and synthesis reports. [Phase 4]
- Benchmark experiments: Cog-RAG vs wiki; hand-rolled loop vs deepagents; Harness-1 as retrieval subagent; Qwen-vs-Gemma voice register; code-graph MCP vs grep-only code tools; tensor-parallel vs one-model-per-card. [Phase 4]
- Conversation-trajectory analytics ("spiral-in" research): replay timestamped transcripts, feedback events, task links, and decision facts to measure hops-to-answer, what was discarded as out of scope versus what resteered, and whether decision-making frameworks improve convergence. Likely its own project; Fawkes only needs to keep collecting the raw material (verbatim turns, task_id on every turn, feedback events, decision-facet facts with source turns). [Far future]

## Tier 3 — Interfaces and reach (Phase 5)

- Web interface: interactive chat, file upload, project creation/management, notes and instructions, authentication and sessions; optional model-target dropdown; workspace, user, and silo areas browsable after sign-in, with area-scoped queries; silo entry by second factor (passkey or authenticator code preferred; a PIN acceptable for re-entry within an app session), device-exclusive silo sessions, separately configurable timeouts; device pairing, revocation, and audit views. [Phase 5]
- Voice-driven project management ("create a new project called X; remember Y"). [Phase 5]
- Back-catalog import: exported Claude/ChatGPT history ingested through `ingest()` with verbatim transcripts, per-day summaries, embeddings, and project assignment — after project scopes exist so structure is preserved. (No iteration-1 conversation logs exist.) [Phase 5]
- Mobile/watch/car clients; multi-room speaker+mic deployment; possible dedicated device. [Phase 5+]
- Claude project-context sync for handoffs (via API context packaging; claude.ai Projects have no public API). [Phase 5]
- Row-level security keyed to user: per-user, per-project memory visibility for additional users/team members; silo Tier B if a second silo is wanted, exercised end to end. [Phase 5]
- Platform integration: iOS via App Intents/Shortcuts ("Hey Siri, ask Fawkes") and a foreground listening mode; Android as the default assistant with a hotword foreground service; device biometrics unlocking a device-bound key on both; own wake-word arbitration across Fawkes microphones (no hook into Apple's multi-device arbitration). [Phase 5+]

## Tier 4 — Eventual / far future (Phase 6+)

- SSM/Mamba ASR replacement for the interim (FastConformer) and final (Canary-Qwen) slots — likely pulled forward to roughly Phase 3.5 for VRAM relief before the second GPU.
- Browser text-extraction sidecar (DevTools-protocol/content-script → `ingest()`) and terminal capture (stdout/tmux) adapters, originally planned for Phase 3 to replace screenshot-to-PDF workflows — deferred; the goal that motivated them (reading screens without installing anything on the host) belongs to the KVM/HID track.
- Screen-context subsystem: accessibility-API-first screen reading (Windows UI Automation / macOS AX / Linux AT-SPI) with event-triggered, perceptual-hash-deduplicated OCR fallback for un-instrumented apps; foundation for a heads-up display (HUD).
- Prompt/context compression for external traffic (headroom-class proxy, cache-aligned live-zone compression) — deferred indefinitely on measured evidence (single-digit-percent real savings); revisit only if external token spend proves material after structured-extraction payloads.
- Microsoft To Do integration; Google Maps/Waze routing with LLM-improved recommendations; home lighting/automation.
- Newsletter/email ingestion and scheduled site scraping → digests and verbal notifications.
- Computer vision pipeline: object recognition/tracking, garage-door and doorway reminders.
- vLLM scale-out / second-opinion serving as hardware grows; Graphiti temporal knowledge graph if bi-temporal SQL hits its ceiling.
- Power management: idle GPU power limits, scheduled indexing windows, standby modes (24/7 availability preserved).
- Fine-tuning experiments (voice register, retrieval policies) only if prompting demonstrably falls short.

## Separate tracks (own repositories, own milestone zero; not scheduled inside Fawkes)

- Cocktail Party speaker-separation research; results folded into Fawkes speech later.
- KVM/HID computer control: HDMI-capture plus USB-HID injection so Fawkes can observe and operate machines with no AI tooling installed (IP-KVM devices first; output-rate control over capture-rate; event-driven agent loop). Held separate until Fawkes Phase 3 exists.

## Explicitly rejected (see Fawkes_Toolbox.md for reasons)

- Summary-first memory (summaries replacing verbatim text) — never.
- Closed-set intent classification as a conversation gate (the Rasa failure mode).
- Hand-built coding harness on the critical path.
- LangChain/LangGraph/deepagents in the voice core.
- Reasoning-driven retrieval (tree traversal, multi-hop reasoning hops, CRAG loops) inside the voice hot path.
- Canary-Qwen LLM mode as the router (scratched 2026-09-06).
- Routing ASR text directly to the research pipeline; discarding text-channel messages; voice output for text input or text output for voice input.
- Tunnels, scope weights, caches, or prompts that cross a silo.
